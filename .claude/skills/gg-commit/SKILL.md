# Commit

`gg do commit` runs the checks of each repo and commits only when they are
green. The message also becomes the `CHANGELOG.md` entry.

## 1. Pick the command for where you are

- **In the ticket folder** — `gg can commit` and `gg do commit` act on
  every repo of the ticket.
- **Inside a single repo**, a standalone one or one repo of a ticket —
  `gg one can commit` and `gg one do commit` act on that repo alone.

The rest of this skill writes `gg do commit`; use the `gg one` form
whenever you are inside a repo.

## 2. Propose a message

Look at `git status` and `git diff` in the repos of the ticket. Propose one
imperative one-liner that says what the step does, not which files changed.
Start from `nextCommitMessage` in `.gg/publish_config.json` of each repo and
update it there if it no longer matches the diff (see the development
guide). Let the user confirm it.

If the user runs `gg do commit` in the ticket folder without `-m`, the
editor already shows each repo's `nextCommitMessage` — `-m` overrides it
with one message for all repos.

## 3. Commit

From the ticket folder:

```bash
gg do commit -m"<message>"
```

From a single repo:

```bash
gg one do commit -m"<message>"
```

Add `-l` when the message must not land in `CHANGELOG.md`.

## 4. On a failing check

`gg do commit` stops at the first red check. Fix the cause, never the check,
then run the command again. Files generated by the DNA are committed
separately as `#gg: generated DNA` — never edit an instance by hand, change
its source under `dna/` instead.

## Important

- Never commit without the confirmed message.
- Never push here — that is `/gg-push`.
